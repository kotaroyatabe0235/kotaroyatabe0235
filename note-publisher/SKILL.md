# note-draft

Markdownファイルを受け取り、note.com の下書きを作成・更新するスキル。

## 前提

- note には記事投稿の公式APIが**無い**。Playwrightで実ブラウザを操作する。
- ログイン情報はファイルに保存しない。`.browser-profile/` にブラウザのプロフィールを残し、
  ユーザーが一度手動でログインした状態を再利用する。
- **draft は絶対に公開しない。** 下書き保存までで止める。
- 公開は `publish` コマンドだけが行う。**ユーザーがその記事を名指しで
  「公開して」と言ったときにだけ**実行する。以下はユーザーとの合意事項:
  - 記事のURLを必ず指定する（取り違え防止）
  - 公開の前に、タイトル・文字数・画像枚数・書き出しを読み上げて見せる
  - `--yes` を付けてよいのは、その会話でユーザーが公開を明示的に頼んだときだけ。
    「あとで公開する」「たぶん公開する」は該当しない
  - 迷ったら `--dry-run` で公開設定の画面まで進み、そこで止めて確認を取る
  - 公開後の取り消し（下書きに戻す）はこのツールでは行わない。noteの画面で操作してもらう

## 場所

`~/workspaces/kotaroyatabe0235/note-publisher/`

## 手順

### 1. 初回のみ：セットアップ確認

`node_modules/` が無ければインストールする。

```bash
cd ~/workspaces/kotaroyatabe0235/note-publisher
npm install
```

### 2. 初回のみ：ログイン

`.browser-profile/` が無い、またはログインが切れている場合、ユーザーに手動ログインを依頼する。

```bash
node src/cli.mjs login
```

ブラウザが開くのでユーザーが手でログインし、ターミナルで Enter を押す。
**この操作はユーザー自身にやってもらう**（コマンドは `!` を付けずに、
macOSのターミナルに貼る形で渡すこと）。

#### ブラウザの窓を開けない場合（SSH越し・iPadからの接続など）

```bash
node src/cli.mjs login --headless
```

メールアドレス（またはnote ID）とパスワードをターミナルで聞き、裏でログインする。
パスワードは画面に表示されず、ファイルにも保存されない。
認証コードを求められた場合はその場で聞き返す。

前提として、noteアカウントに**パスワードが設定されている**必要がある。
X（Twitter）やGoogleでの連携ログインしか使っていない場合はパスワードが無いことがあるので、
先に手元のブラウザ（スマホ・タブレットでよい）で
`https://note.com/settings/account` からパスワードを設定してもらう。
パスワードを忘れている場合は `https://note.com/password_resets` から再設定できる。

連携ログイン（Xでログイン）自体の自動化はしない。X側のbot検知が厳しく、
安定しないうえに X のパスワードまで預かることになるため。

### 3. 下書きを作る／書きかえる

新規作成:

```bash
node src/cli.mjs draft <Markdownファイルのパス>
```

既存記事の書きかえ:

```bash
node src/cli.mjs draft <Markdownファイルのパス> --url https://note.com/<ユーザー名>/n/<記事キー>
```

オプション:

- `--title "タイトル"` — Markdown の先頭 `# 見出し` ではなく、指定した文字列をタイトルにする
- `--headless` — ブラウザの画面を出さずに実行する

### 4. 公開する（ユーザーが明示的に頼んだときだけ）

```bash
node src/cli.mjs publish --url https://note.com/<ユーザー名>/n/<記事キー>
```

- 中身を読み上げたあと、**記事のタイトルを打ち込む**と公開される
- `--yes` で打ち込みを省ける。Claudeが代わりに実行する場合はこれを使うが、
  使ってよいのは上の合意事項を満たすときだけ
- `--dry-run` は公開設定の画面まで進んで止まる。公開はしない
- すでに公開済みの記事は何もせず終了する
- 公開後は note の API（`/api/v3/notes/<記事キー>`）で `status` を確かめ、
  `published` になっていることを確認してから報告する

### 5. うまく動かないとき

note の画面の作りが変わるとセレクタがずれる。その場合:

```bash
node src/cli.mjs probe
```

を実行して出力された JSON を確認し、`src/note.mjs` の
`TITLE_SELECTORS` / `BODY_SELECTORS` と `saveDraft()` の候補リストを直す。

## 仕様メモ

- Markdown の先頭 `# 見出し` がタイトルになり、本文からは取り除かれる。
- 本文は Markdown → HTML に変換し、`paste` イベントとしてエディタに流し込む。
  note のエディタ（ProseMirror）が自前で見出し・太字・リストに変換してくれるため、
  note 独自の内部フォーマットを手で組み立てる必要がない。
- 画像は `![説明](fig.png)` の**行だけの書き方**に対応。相対パスはMarkdownファイルの
  置き場所を起点に解決する。`![]()` の説明文はnoteのキャプション欄に入る。
  `http(s)://` の画像はこのパソコンに無いので飛ばし、その旨を表示する。
- 画像の入れかたは本文とは別処理。本文にはまず `⟦note-image-0⟧` という目印を置いて
  貼り付け、そのあと目印の段落を消して**画像ファイルをpasteする**。
  noteのエディタがpasteを受け取ると自分でアップロードして `assets.st-note.com` の
  画像に変えてくれる。HTMLに `<img src="ローカルのパス">` と書いても保存されない。
- 目印を消した跡に空行が残るので、後片付けで消している。
  このとき Backspace を使うと**ひとつ上の画像を消してしまう**ので、
  上の行の末尾にカーソルを置いて Delete で引き寄せる方式にしてある。
  画像や文字が減ったら Cmd+Z で戻して後片付けを打ち切る安全装置つき。

## 注意

- note の利用規約には「運営に支障が生じると判断した場合」利用停止できる条項がある
  （クリエイター規約 10.1.8）。自動化はグレーゾーンであることをユーザーは了解済み。
- 短時間に何度も実行しない。目安として 10リクエスト/分 を超えない。
- `.browser-profile/` は `.gitignore` 済み。**絶対にコミットしない**（セッションCookieが入っている）。
