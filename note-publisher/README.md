# note-publisher

Markdownファイルを渡すと、note(note.com)の**下書き**を作ったり書きかえたりするツール。
Claude Code の Skill としても使えます。

## だいじな前提

- noteには「外から記事を投稿する公式の窓口(API)」が**ありません**。
  なので、Playwrightで本物のブラウザを裏で動かして、人と同じ操作をしています。
- **下書きを作るだけでは、公開されません。** `draft` は下書き保存で止まります。
  公開されるのは `publish` を自分で実行したときだけです。
- `publish` は取り消しがきかない操作なので、**記事のタイトルを打ち込むまで実行しません**。
- noteの規約には「運営に支障が生じると判断した場合」利用を止められる条文があります
  (クリエイター規約 10.1.8)。自動化はグレーゾーンです。
  短い時間に何度も実行しないでください(目安: 10回/分より少なく)。

## 準備

### 1. ライブラリを入れる

```bash
cd ~/workspaces/kotaroyatabe0235/note-publisher
npm install
```

### 2. 最初に1回だけログインする

```bash
node src/cli.mjs login
```

ブラウザが開きます。**自分の手で**noteにログインしてください。
終わったらターミナルに戻って Enter を押します。

ログインした状態は `.browser-profile/` というフォルダに残るので、次回からは不要です。

> `.browser-profile/` にはログイン情報(Cookie)が入っています。
> `.gitignore` で除外していますが、**絶対に他人に渡さないでください**。

#### ブラウザの窓が開けないとき（SSH越し・iPadからつないでいるときなど）

```bash
node src/cli.mjs login --headless
```

メールアドレス（またはnote ID）とパスワードをターミナルで聞かれます。
パスワードは打っても画面に出ませんし、ファイルにも保存されません。
残るのは `.browser-profile/` のログイン状態だけです。

このやり方には、noteアカウントに**パスワードが設定されている**ことが必要です。
X（Twitter）やGoogleの連携ログインしか使っていないとパスワードが無い場合があるので、
そのときは手元のブラウザ（スマホやタブレットでOK）で
`https://note.com/settings/account` からパスワードを設定してください。
忘れた場合は `https://note.com/password_resets` から再設定できます。

## つかいかた

### 新しい下書きを作る

```bash
node src/cli.mjs draft ~/memo/kiji.md
```

Markdownの一番最初の `# 見出し` が、そのまま記事のタイトルになります。

### すでにある記事を書きかえる

```bash
node src/cli.mjs draft ~/memo/kiji.md --url https://note.com/ユーザー名/n/nXXXXXXXX
```

### 公開する

自分の目で下書きを確かめ、これでいいと決めてから実行します。

```bash
node src/cli.mjs publish --url https://note.com/ユーザー名/n/nXXXXXXXX
```

こう表示されます。

```
これから公開する記事:
  タイトル : SPI 0.96 は「ほぼ順調」ではなかった
  本文     : 2270 文字（39 かたまり）
  画像     : 2 枚
  書き出し : EVM を導入したのに、遅れの検知が最後まで遅れた話。…

公開設定の画面まで進みました。ここまでは、まだ下書きのままです。

本当に公開する場合は、記事のタイトルをそのまま打ってください。
（やめる場合は、何も打たずに Enter）
タイトル:
```

**タイトルを打ち込むまで公開されません。** `y` のような一文字ではなく
タイトルを打たせているのは、うっかり指が滑って公開してしまうのを防ぐためです。

公開したあとは、note の記録を見て本当に `published` になったか確かめ、
記事のURLを表示します。

公開をやめる（下書きに戻す）操作は、このツールには入れていません。
noteの画面で行ってください。

### オプション

| オプション | いみ |
|---|---|
| `--title "タイトル"` | Markdownの見出しではなく、これをタイトルにする |
| `--headless` | ブラウザの画面を出さずに裏で動かす |
| `--dry-run` | `publish` で、公開の一歩手前まで進んで止まる |
| `--yes` | `publish` で、タイトルの打ち込みによる確認を省く |

## うまく動かないとき

noteの画面の作りが変わると、部品を見つけられなくなることがあります。
そのときはこれを実行してください。

```bash
node src/cli.mjs probe
```

今の画面にある入力欄やボタンの一覧が出ます。
その内容をClaudeに見せると、`src/note.mjs` の目印(セレクタ)を直せます。

## 仕組み

```
Markdownファイル
  ↓ marked で変換
HTML
  ↓ 「貼り付け」の出来事として流し込む
noteのエディタ(ProseMirror)
  ↓ noteが自分で見出し・太字・リストに変換してくれる
下書き完成
```

1文字ずつ打ち込むのではなく「HTMLを貼り付けた」ことにするのがポイントです。
こうすると、note独自の内部フォーマットを自分で組み立てなくて済みます。

## 画像について

Markdownに画像の行を書いておけば、noteに預けて（アップロードして）記事に入ります。

```markdown
![毎週見ていた指標（SPI）](fig-spi.png)
```

- ファイルの場所は、**Markdownファイルの置き場所からの道のり**で書きます
- `![ ]` の中の説明文は、noteの**キャプション欄**に入ります
- `![説明](fig.png)` **だけが書かれた行**が対象です（文章の途中に混ぜた画像は対象外）
- `https://…` で始まるネット上の画像は、このパソコンに無いので飛ばします

### なぜ画像だけ別あつかいなのか

文字はHTMLを1回貼り付ければ全部入りますが、画像はそうはいきません。
記事に出せるのは**noteのサーバーに預けた画像だけ**で、HTMLに
「このパソコンの中の fig.png を表示して」と書いても、保存すると消えてしまいます。

そこでこのツールは、本文にはまず `⟦note-image-0⟧` という目印だけを置いておき、
本文を入れ終わってから、目印を1つずつ「画像ファイルを貼り付けた」ことにして
入れ替えています。noteのエディタは貼り付けを受け取ると、自分でアップロードして
画像に変えてくれます。

## できないこと

- 有料記事の設定
- ハッシュタグの自動付与
- 文章の途中に混ぜこんだ画像（行として独立していない画像）
